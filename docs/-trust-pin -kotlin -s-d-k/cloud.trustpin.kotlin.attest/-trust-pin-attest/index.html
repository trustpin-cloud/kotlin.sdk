TrustPinAttest

class TrustPinAttest

Proves to your backend that requests come from your genuine app on a genuine Android device.

Set up pinning first, then attestation:

TrustPin.setup(TrustPinConfiguration.fromAssets(context).withAndroidStorage(context))
TrustPinAttest.setup(context, TrustPinAttestConfiguration.fromAssets(context))
TrustPinAttest.bindToHeader("Authorization")
TrustPinAttest.prefetch()
Content copied to clipboard

Requests to the configured hosts then carry an attestation token in the TrustPin-Attestation header: automatically through TrustPin's OkHttp and Ktor adapters, and through attestationHeaders for other clients. Calls to your verifier are pinned by the TrustPin instance with the same identifier; register the verifier's domain in your TrustPin project.

The SDK never blocks or fails your requests: when no token is available, requests are sent without the header and your backend decides how to treat them.

Attestation is designed for one process per app: set it up in the process that performs your networking. Two processes attesting at the same time are harmless but spend evidence quota twice.

@JvmOverloads
suspend fun attestationHeaders(url: String, requestHeaders: Map<String, List<String>> = emptyMap()): Map<String, String>

The attestation headers for a request to url: the TrustPin-Attestation header, or an empty map. Only https URLs to the configured hosts receive the header. requestHeaders supplies the bound header when bindToHeader is used. Never throws. If your client follows redirects itself, do not carry the header to the redirect's destination: turn automatic redirects off, or rebuild each redirect's headers with TrustPin.redirectedRequestHeaders.

fun setTokenBinding(value: String?)

Binds every token to value, typically the session's Authorization header value. The value never leaves the device; your backend compares the token's binding with the value it receives. A change may start a token renewal in the background. null removes the fixed binding; header binding set with bindToHeader stays in force.
